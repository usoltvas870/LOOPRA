# NURA Real Script Provider

Stage 5K adds one bounded real-provider path after the Stage 5J Script Input
contract. It currently supports `TALKING_GUIDE` and leaves every successful
result in `DRAFT_AWAITING_HUMAN_REVIEW`; it neither creates an Episode Input
Package nor starts an Episode bridge.

The adapter is `deepseek-nura-script` version `1.0`. It uses model
`deepseek-v4-flash` through the existing shared DeepSeek HTTP transport,
credential boundary (`DEEPSEEK_API_KEY`), timeout, JSON mode and error
classification. This prevents a second client implementation. Thinking is
disabled, structured JSON is requested, and the adapter has a distinct prompt
contract: `nura-script-generation` version `1.3` for future calls.

The provider-facing request is built only from one Script Input identity, one
candidate and rank, the requested format, approved mechanism and hook,
mandatory revisions, prohibited copying elements, bounded evidence/safety
constraints, profile identity and format principles. It does not include the
full editorial Markdown, Production Brief Markdown, review document, OCR or
transcript corpus, raw evidence, local paths, credentials, source media, or
other ranks.

The runner is:

```text
python trend-radar/run_nura_real_script_provider_acceptance.py --provider-mode real --format TALKING_GUIDE --json
```

It selects the canonical Rank 1 brief by default. `--provider-mode reuse`
requires no credential and makes no HTTP request; it accepts only a matching,
hash-verified validated artifact.

Runtime artifacts live below `trend-radar/data/nura-real-script-provider/`,
which is already ignored as part of `trend-radar/data/`. A bounded request,
Script Input, raw provider response, validation report, validated output and
pending review package are atomically persisted there. The raw response is
saved before response parsing and validation; invalid responses therefore
remain diagnosable but are never saved as validated Script Output.

The trusted application attaches identity and provenance envelope fields. It
then runs Stage 5J identity/safety validation plus deterministic TALKING_GUIDE
opening, structure, lamp-metaphor and music-primary-meaning checks. The
provider returns advisory constraint IDs and block IDs. The application alone
materializes exact, unchanged block text as resolved evidence. Provider notes
and claimed spans are diagnostics only: a bad optional span produces a warning,
while an unknown constraint or block remains a hard failure. Semantic quality
and non-imitation remain human review questions. A successful draft receives a pending
human-review package with `human_confirmation=false` and
`episode_bridge_ready=false`. Subjective editorial quality and non-imitation
remain human checks. Rank 1 is used only by the acceptance runner; the provider
does not make a rank selection. Ranks 2–5 are not generated by this stage.

`--reprocess-raw <raw_provider_response.json> --offline` reprocesses an
existing successful HTTP response with zero network calls and no credential.
It preserves the raw artifact and records original provider/prompt provenance,
the current parser/validator/resolution versions, and the legacy request-hash
limitation. Prompt `1.2` remains the provenance of attempt 3; prompt `1.3` is
not applied retroactively.
